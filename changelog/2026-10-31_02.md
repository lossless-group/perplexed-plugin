## Why Care?

The context-vigilance kit has a baseline frontmatter template: `title`,
`date_created`, `date_modified`, `site_uuid`, `hex_code`, `authors`. Every
doc that carries all of them can be sorted, linked, and rolled up the same
way as every other doc in the tree.

This pass fills only what's missing, and only from facts. Nothing is
guessed, no existing value changes meaning, and no date is set to the day
of the sweep.

## What's New?

- **`date_modified: 2026-08-18`** on eight docs, the date of each file's
  last commit before this sweep.
- **`authors: [Michael Staton]`** on the partials-and-preambles issue, its
  only human commit author.
- **`status` in Title-Case** on two issues: `open` is now `Open`, and
  `resolved` is now `Resolved`.
- **`augmented_with` as a one-item list** on both 2026-05-02 plans and the
  Obsidian-API reminder; the tool strings are unchanged.

The other seven docs already carried the template and are untouched. The
two 2026-05-02 plans keep their legacy `created:` key: each already has a
`date_created` with the same value, so a rename would duplicate the key.

Part of the tree-wide sweep planned in the context-vigilance kit:
`ai-labs/context-vigilance-kit/context-v/plans/Retrofit-Every-Repo-to-OKF-Then-the-Kit-Frontmatter.md`.
